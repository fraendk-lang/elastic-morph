# Realtime Export Resolution Race Fix Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make "Direkt Export" (the realtime MediaRecorder path) actually record at the chosen format's true resolution, as its own code comment already claims it does — currently a resize-order race silently reverts it to the smaller on-screen canvas size.

**Architecture:** Add one boolean flag, `S.rtExportArming`, that is true only during the synchronous window between "we've set `S.exportRes` and called `resize()`" and "`recorder.start()` has run" in the `exportBtn` click handler. Every place that decides whether `S.exportRes` is honored vs. wiped (`exportResActive()` in `src/inject-v75.js`, and the inline guard in the base `resize()` in `elastic-morph.html`) gains this flag as a third accepted signal alongside `S.exporting` and `recorder.state === "recording"`.

**Tech Stack:** Single-file vanilla JS app (`elastic-morph.html`), partly regenerated by `node build.js` from `src/inject-vNN.js`, zero-dependency static-assertion test harness (`test.js`).

## Root Cause (already investigated — do not re-investigate)

In the `exportBtn` click handler, the sequence is: `S.exportRes = res; resize();` … *(sync, no await)* … `recorder = new MediaRecorder(...)` … `recorder.start(2000)`. At the `resize()` call, `S.exportRes` is set but `S.exporting` is `false` (only `exportHQ()` sets that) and `recorder` is either `null` or a stopped recorder from a prior export — so `recorder.state !== "recording"`. Both the v75 `resize` wrapper (`src/inject-v75.js:16-21`) and the base `resize()`'s own inline guard (`elastic-morph.html`, `if (S.exportRes && (S.exporting || (recorder && recorder.state === "recording")))`) therefore treat `S.exportRes` as stale, null it, and size the canvas to `w * S.quality` (on-screen size). `captureStream()` then captures that smaller canvas for the whole recording. Confirmed live 2026-09-07: during an active realtime recording, `S.exportRes` was `null` and the canvas stayed at on-screen dimensions. `exportHQ()` (offline) is unaffected — it sets `S.exporting = true` first.

## Global Constraints

- The fix must not change `exportHQ()` (offline export) behavior at all — it already works via the `S.exporting` signal.
- `src/inject-v75.js` is build-injected: edit that file, then run `node build.js` before `node test.js`. Do NOT hand-edit the generated `exportResActive` copy inside `elastic-morph.html`.
- `S.rtExportArming` must be cleared on every exit path from the arming window: after `recorder.start()` succeeds, AND in the handler's `catch (err)` block. It must never be left `true` after the click handler returns.
- No new UI, no new user-facing behavior beyond "the realtime export file is now the intended resolution."
