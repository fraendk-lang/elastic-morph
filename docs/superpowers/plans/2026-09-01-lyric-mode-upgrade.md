# Lyric Mode Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix Karaoke Wipe's fixed-duration timing bug, add a next-line preview, and add a 4th
"Hypno" Lyrics Studio preset.

**Architecture:** A new pure helper function (`lyricWipeDuration`) plus 3 small edits inside
`drawTextLayer`'s lyric-mode handling, plus one new array entry in `LYRICS_STUDIO_PRESETS`.

**Tech Stack:** Vanilla JS, no new dependencies.

## Global Constraints

- Edits A/B/C (the helper function + `drawTextLayer`'s 3 touch points) are pre-`@BUILD-INJECT-V58`
  marker (currently line 10812) in `elastic-morph.html`.
- **Edit D is different and easy to get wrong**: `LYRICS_STUDIO_PRESETS` is declared in
  `src/inject-v104.js`, not directly in `elastic-morph.html` — the array's appearance in
  `elastic-morph.html` (currently ~line 16890) is a POST-marker mirror regenerated by
  `node build.js` on every run. Edit `src/inject-v104.js`, never hand-edit the
  `elastic-morph.html` mirror — it is silently overwritten on the next build. This was confirmed
  by grepping `src/` fresh before writing this plan (a prior assumption in this plan's own design
  spec that "no `src/` involvement expected" turned out wrong for this one edit specifically —
  always verify, never assume, for this codebase).
- `currentLyric` (called from `src/inject-v104.js:175`, and from `drawTextLayer`) and
  `drawTextLayer` itself are NOT redeclared/wrapped in `src/inject-v104.js` — only referenced by
  call. `drawTextLayer` IS wrapped post-marker elsewhere (`src/inject-v98.js`, the Canvas Text
  Live Toggle from an earlier round) but that wrapper only forwards its existing parameters
  unchanged — this task doesn't change `drawTextLayer`'s signature, so that wrapper needs no
  changes this round.
- Test count baseline: 638 passed, 0 failed (confirmed via an actual `node test.js` run just
  before this plan was written). Required after this task: exactly **645 passed, 0 failed** (638

Append to `test.js`, right before the `/* ---------------- summary ---------------- */` block:

```js
section("Lyric Mode upgrade — adaptive wipe, next-line preview, Hypno preset");

ok("lyricWipeDuration is defined and called from drawTextLayer's lyric-mode setup", (() => {
  const fn = extractFn("lyricWipeDuration");
  const caller = extractFn("drawTextLayer");
  return !!fn && !!caller && caller.includes("lyricWipeDuration(cur.line.t, next ? next.t : null)");
})());

ok("lyricWipeDuration clamps correctly in all 4 cases: passes a normal gap through, clamps a long gap down to 2.4, clamps a very short gap up to 0.6, and falls back to 2.4 when there's no next cue (genuine behavioral check via loadFns, not a structural text match)", (() => {
  const { lyricWipeDuration } = loadFns(["lyricWipeDuration"]);
  const normal = Math.abs(lyricWipeDuration(10, 11) - 1.0) < 1e-9;      // 1.0s gap, passes through
  const long = Math.abs(lyricWipeDuration(10, 14) - 2.4) < 1e-9;        // 4.0s gap, clamped down
  const short = Math.abs(lyricWipeDuration(10, 10.2) - 0.6) < 1e-9;     // 0.2s gap, clamped up
  const noNext = Math.abs(lyricWipeDuration(10, null) - 2.4) < 1e-9;    // last cue, no next
  return normal && long && short && noNext;
})());

ok("drawTextLayer's lyric-mode setup declares lyricNextText, computes the next cue, and sets S.lyricWipeDur via lyricWipeDuration", (() => {
  const fn = extractFn("drawTextLayer");

         fn.includes("const next = LY.cues[cur.idx + 1];") &&
         fn.includes("lyricNextText = next ? next.text : \"\";") &&
         fn.includes("S.lyricWipeDur = lyricWipeDuration(cur.line.t, next ? next.t : null);");
})());

ok("the Karaoke Wipe branch uses S.lyricWipeDur in lyric mode and keeps the original fixed 2.4 otherwise", (() => {
```
